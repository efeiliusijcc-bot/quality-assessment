适用于：质量评估软件平台、深度学习模型读取、知识图谱同步与生产质量看板

1. 设计目标

视图层的目标不是替代底层表，而是将分散在批次、工序、参数、质量检测、缺陷、评估和知识图谱中间表中的数据进行业务化组织。

面向前端展示：将多张表关联成批次总览、工序执行明细、缺陷明细、评估结果等可直接展示的数据结构。

面向算法读取：将参数、质量指标、缺陷记录整理为长表或 JSON 快照，便于深度学习、质量评估模型和超多目标优化算法读取。

面向知识图谱同步：将 PostgreSQL 中的 kg.kg_entity 与 kg.kg_relation 规范化导出，作为 Neo4j 节点和关系导入来源。

面向统计看板：通过物化视图保存高频统计结果，减少前端大屏和历史趋势查询时的多表聚合压力。

2. 视图分层原则

建议将视图分成四类：生产过程视图、质量检测视图、评估优化视图、图谱导出视图。对统计汇总和大屏展示使用物化视图。

5. 物化视图设计

物化视图适合放置高频统计结果，例如工序合格率、缺陷频次、批次质量看板。普通视图每次查询都会动态关联底层表，而物化视图会保存查询结果，因此查询更快，但需要定期刷新。

物化视图

统计内容

建议刷新频率

prod.mv_batch_process_progress

每个批次的工序执行数量、完成数量、异常数量、涉及工序

生产中每 5-10 分钟刷新一次；生产结束后手动刷新

qc.mv_step_quality_pass_rate

每个工序、每个质量指标的检测数量、合格数量、失败数量、合格率、均值、最大最小值

质量检测数据导入后刷新

qc.mv_step_defect_statistics

每个工序、每类缺陷的缺陷记录数、缺陷总数、平均尺寸、严重缺陷数

AOI/视觉检测结果导入后刷新

eval.mv_batch_quality_dashboard

批次级质量总览，包括合格率、缺陷数量、关键缺陷数、最新评估结论

首页或大屏展示前刷新，或定时刷新

物化视图刷新 SQL 示例：

REFRESH MATERIALIZED VIEW prod.mv_batch_process_progress;

REFRESH MATERIALIZED VIEW qc.mv_step_quality_pass_rate;

REFRESH MATERIALIZED VIEW qc.mv_step_defect_statistics;

REFRESH MATERIALIZED VIEW eval.mv_batch_quality_dashboard;

6. 与 Neo4j/GAT 的数据对接

PostgreSQL 负责存储完整的业务数据和中间结果，Neo4j 负责表达工序、参数、缺陷、质量指标之间的关系网络。因此需要专门的导出视图，将 PG 中的实体、关系和 GAT 权重转换为适合图数据库导入的数据结构。

导出视图

导出对象

用途

kg.v_neo4j_node_export

知识图谱节点

将 kg.kg_entity 导出为 Neo4j 节点，包含 node_id、node_label、entity_name、properties

kg.v_neo4j_relation_export

知识图谱关系

将 kg.kg_relation 导出为 Neo4j 边，包含 source_node_id、target_node_id、relation_type、confidence、evidence_payload

kg.v_gat_relation_weight_export

GAT 注意力权重

将 GAT 输出写入 Neo4j 边属性，如 attention_weight、hidden_relation_flag

典型同步逻辑如下：

-- 1. 从 kg.v_neo4j_node_export 读取节点数据，写入 Neo4j 节点

-- 2. 从 kg.v_neo4j_relation_export 读取关系数据，写入 Neo4j 关系

-- 3. 从 kg.v_gat_relation_weight_export 读取注意力权重，更新 Neo4j 关系属性

-- 4. Neo4j 中的关系可保留 source='RULE/APRIORI/GAT/MANUAL' 与 weight/confidence 信息

7. 在 Navicat 中执行和维护

第一步：确认已经在目标数据库中执行过 pg_quality_assessment_schema.sql，并且 app、core、prod、qc、eval、kg、etl 等 schema 已经创建成功。

第二步：在 Navicat 左侧选中目标数据库，例如 CCTV，打开查询窗口。

第三步：执行随文附带的 pg_quality_assessment_views.sql 文件。执行完成后，在 prod、qc、eval、kg 等 schema 下可以看到对应视图和物化视图。

第四步：普通视图不需要刷新，底层表数据变化后查询结果会自动变化；物化视图需要执行 REFRESH MATERIALIZED VIEW。

第五步：如果后续修改物化视图定义，需要先 DROP MATERIALIZED VIEW，再重新 CREATE。普通视图可以直接 CREATE OR REPLACE VIEW。

Navicat 查询示例：

SELECT * FROM prod.v_process_run_detail LIMIT 20;

SELECT * FROM prod.v_process_parameter_long WHERE is_out_of_limit = true;

SELECT * FROM qc.v_defect_detail WHERE is_critical = true;

SELECT * FROM eval.mv_batch_quality_dashboard ORDER BY latest_assessment_time DESC NULLS LAST;

    ps.step_code,

    ps.step_order,

    ps.is_inspection,

    ws.station_id,

    ws.station_code,

    ws.station_name,

    eq.equipment_name,

8.2 参数 JSON 汇总视图

CREATE OR REPLACE VIEW prod.v_process_run_parameter_json AS

SELECT

    pr.run_id,

    b.batch_id,

    b.batch_no,

    pu.unit_id,

    pu.serial_no,

    ps.step_id,

    ps.step_code,

    ps.step_name,

    jsonb_object_agg(

        pd.param_name,

        COALESCE(

            to_jsonb(pv.value_num),

            to_jsonb(pv.value_text),

            to_jsonb(pv.value_bool),

            to_jsonb(pv.value_time),

            pv.value_json,

            CASE WHEN pv.file_id IS NOT NULL THEN jsonb_build_object('file_id', pv.file_id, 'file_name', fr.file_name, 'file_path', fr.file_path) END

        )

    ) FILTER (WHERE pv.value_id IS NOT NULL) AS parameter_json,

    jsonb_object_agg(pd.param_name, pv.quality_flag) FILTER (WHERE pv.value_id IS NOT NULL) AS parameter_quality_json

FROM prod.process_run pr

JOIN prod.production_batch b ON pr.batch_id = b.batch_id

LEFT JOIN prod.product_unit pu ON pr.unit_id = pu.unit_id

JOIN core.process_step ps ON pr.step_id = ps.step_id

LEFT JOIN prod.parameter_value pv ON pr.run_id = pv.run_id

LEFT JOIN core.parameter_def pd ON pv.param_id = pd.param_id

LEFT JOIN core.file_resource fr ON pv.file_id = fr.file_id

GROUP BY pr.run_id, b.batch_id, b.batch_no, pu.unit_id, pu.serial_no, ps.step_id, ps.step_code, ps.step_name;

8.4 Neo4j 节点导出视图

CREATE OR REPLACE VIEW kg.v_neo4j_node_export AS

SELECT

    e.entity_id::text AS node_id,

    e.entity_type,

    CASE e.entity_type

        WHEN 'PROCESS' THEN 'ProcessStep'

        WHEN 'PARAMETER' THEN 'Parameter'

        WHEN 'QUALITY_METRIC' THEN 'QualityMetric'

        WHEN 'DEFECT' THEN 'DefectType'

        WHEN 'EQUIPMENT' THEN 'Equipment'

        WHEN 'BATCH' THEN 'Batch'

        WHEN 'PRODUCT' THEN 'ProductType'

        ELSE 'Entity'

    END AS node_label,

    e.entity_code,

    e.entity_name,

    e.ref_schema,

    e.ref_table,

    e.ref_id::text AS ref_id,

    e.properties,

    e.graph_version_id::text AS graph_version_id,

    e.created_at

FROM kg.kg_entity e;

9. 后续扩展建议

如果前端页面需要固定字段展示，可以在现有视图基础上再建立页面专用视图，例如 v_dashboard_home、v_station_quality_panel。

如果算法模型需要固定输入矩阵，建议基于 prod.v_process_parameter_long 生成训练集抽取 SQL，避免直接读取底层参数值表。

如果数据量变大，建议为高频筛选字段增加索引，同时将质量趋势、缺陷趋势、批次看板等统计结果改为物化视图。

如果需要做到准实时看板，可以使用定时任务刷新物化视图，例如每 5 分钟刷新生产进度，每 10 分钟刷新质量统计。

如果后续引入数据权限，可在视图中增加用户权限过滤，或者使用 PostgreSQL Row Level Security 进行行级控制。
